# 小岛渲染

核对日期：2026-10-11。`SceneCanvas.tsx` 是 React Three Fiber 显示层，输入真实 SceneSnapshot，数据变更由上层 VoxelEngine 完成。

每个完整1×1×1方块共享几何体与轻微边缘纹理，通过 InstancedMesh 批量显示。快照顺序与槽位同步维护，拾取的 instanceId 立即映射回稳定 voxelId。新增与移动只在显示层进行短暂补间；不影响快照、撤销、服务端提交摘要。动画结束后停止请求帧，用户设置减弱动效时直接落位。

`mode` 为 orbit/build/paint；后两者回传 `{ voxelId, normal }`，不自行修改场景。`viewAction` 使用递增 seq 触发缩放/重置。主场景使用40°垂直视场的透视相机。初次加载、容器变化及复位通过`cameraFraming.framePerspectiveScene`将每个实际体素的八角投影约束到浮层之间的可用区域，按深度求相机距离；`setViewOffset`偏移视锥，轨道中心仍在小岛上。按钮与滚轮均以相机到轨道中心的距离缩放，普通编辑保持视角。

2026-10-11透视切换：`cameraFraming.test.ts`覆盖桌面、竖屏、窄横屏的所有体素角点取景，以及空场景/坐标边缘和裁剪范围，4项通过；最终类型检查与构建通过。实际浏览器检查1440×900与390×844取景、放大/缩小/旋转/复位通过，阴影与AO保留，无控制台error；未改动作品数据，真实设备触控仍待验收。光照及GTAO参数保持；方向光自身的阴影相机继续使用正交投影，与观察相机独立。官方依据：[PerspectiveCamera](https://threejs.org/docs/pages/PerspectiveCamera.html)、[OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)，本地核对Three r186与three-stdlib实现。

## 调试选择与分组

`SceneCanvas.debugSelection`接收`{kind:'group'|'part',id}`或null。`SelectionBounds`依据已提交快照选出成员partId，再用真实体素世界坐标计算边界并留出轻微边距；空部件不绘制框。它不改变快照、相机、部件归属或拾取结果，不投影，也不参与GTAO遮挡；关闭调试面板时传null，R3F卸载并释放声明式Box3Helper的几何与材质。

“物件组→部件”的权威关系来自共享协议及VoxelEngine，显示层不按名称或ID前缀猜测。整组/子部件的编辑先由内核原子提交，再按原有实例更新和短时动画显示；保存与撤销由上层负责。旧作品没有groups或groupId时仍按原有部件渲染。2026-10-11已独立检查隔离快照的桌面整组移动/撤销、碰撞回滚、子部件改色/撤销及面板关闭，390×844下滚动编辑可用、无横向溢出；没有沿用下文阴影阶段结果代替本次检查。隐藏入口及完整验证证据见根目录[实现地图](../../../../PROJECT_MAP.md)，最终状态与样式调整后的构建通过，真实设备体验仍待验收。

## 光照与后处理

按用户最新要求使用透视观察相机、方向光投影与屏幕空间 AO，保持 Lambert 材质、原有光照强度和透明背景。当前 Three.js 为 0.186.1；复用其官方 [GTAOPass](https://threejs.org/docs/pages/GTAOPass.html)，不新增渲染依赖。N8AO 候选未采用：本项目需要明确释放 GPU 资源，核对版本的完整清理接口不足；当前方案的代价是自行管理少量后处理生命周期与透明合成。

- `SceneLighting`：主灯使用 2048×2048 的 PCFShadowMap。`SceneCanvas` 把当前/前一快照、2.5 格落下动画和沿主光方向投射的接影地面纳入边界；阴影相机随场景更新，灯光方向不变。实例裁剪包围体同样包含动画起终点。地面仅接收半透明投影，不参与拾取。
- `ScenePostprocessing`：原始场景 → GTAO/Poisson 去噪 → 透明 sRGB 输出 → FXAA。AO 半径按世界单位计算（2.2 格），透视相机移动不会改变其世界尺度。透明接影面和拾取高亮只从法线/深度阶段排除，避免成为错误遮挡物；beauty 阶段保留。AO 阶段复用刚生成的阴影，不再次计算阴影贴图。
- 透明输出：`RenderPass.clearAlpha = 0` 保证首次手动清屏透明；当前 `flat` 关闭色调映射，输出着色器先解除线性颜色预乘，再做 sRGB 编码并恢复预乘，避免网格和阴影边缘发白。以后改变色调映射或输出色彩空间时需同步更新该输出通道。
- 按需帧不变：动画、相机和编辑触发重绘，后处理不自行请求持续帧。容器/DPR 变化重设目标尺寸；卸载释放 composer、各 pass、阴影贴图和手工纹理（补齐 r186 GTAOPass 遗漏的两份材质）。R3F 管理声明式几何和材质，Drei 管理相机监听。

2026-10-11 验证：构建与类型检查通过；1440×1024、390×844 实际渲染、旋转、缩放、复位通过。隔离页面验证方块 ID/法线拾取及三次画布卸载重建，最终无新增控制台错误；临时页面已清理。未测真实移动设备帧率或长期 GPU 内存趋势。

## 初版照明经验（阴影方案已被上文替代）

2026-10-11首屏对照发现：高光照与默认色调映射导致颜色发白，较大的颜色随机差异形成棋盘纹理，不透明地面制造矩形背景边界。首轮修正为较低光照、直接色彩输出、同材质小幅色差和透明阴影；复查显示整体过暗。依据当前Three.js r186着色器中irradiance经过Lambert BRDF除以π的实际实现，最终采用纯Lambert材质与π归一化的充分环境/补光，不再沿用PBR高光；移除方向光长投影，仅保留柔接触影。造型与材质配色未在第二轮改变。后续颜色问题先区分材质颜色、光照/色调映射与背景，不以继续加饱和度掩盖来源。

需要在浏览器检查真实画面、触控拾取和资源趋势；内核测试或截图均不代表儿童实际使用体验已验收。
