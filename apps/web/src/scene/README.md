# 小岛渲染

核对日期：2026-10-11。`SceneCanvas.tsx` 是 React Three Fiber 显示层，输入真实 SceneSnapshot，数据变更由上层 VoxelEngine 完成。

静态体素由 `VoxelSurface / VoxelSurfaceView` 按32格分块：密集区域只输出外露面，稀疏区域与动画中的体素使用共享方块的 InstancedMesh。保留每格颜色、单位纹理和完整作品数据。新增整批落位与移动补间只在显示层进行；不影响快照、撤销、服务端提交摘要。动画结束后停止请求帧，用户设置减弱动效时直接落位。

## 表面缓存与局部更新（2026-10-11）

调用链：`SceneCanvas.VoxelWorld → VoxelMotion.sync → VoxelSurfaceView.sync → VoxelSurface.sync/rebuild`。保存和AI仍使用完整单位体素，不引入可变尺寸数据或存档迁移。缓存只适用于当前不透明、轴对齐的方块。

- `VoxelSurface` 按稳定ID比较位置和颜色，先删除旧占位再写新占位，支持同批交换位置。改色只重建本块；增删和移动还检查六邻域所在块，负坐标向下取整。未受影响块保留原几何；当前完整快照的差异扫描仍为O(N)，不能把局部GPU更新宣称为整条链路的常数开销。
- 密实块仅生成与空位置相邻的面，跨颜色/部件的内部面也省略；单位面的绕序、法线、UV直接沿用当前Three.js `BoxGeometry`，颜色保持线性顶点色，方格边缘纹理不拉伸。若外露面超过本块方块数的三倍，保留共享立方体实例，避免零散场景为少量剔除大幅扩张顶点缓冲。
- 动画中的体素暂时从静态占位中移出，邻居保留可能露出的面；它们使用独立实例批次，仍首帧整体出现、按既定时长移动。`advance`只更新活动实例，结束时将已落位体素交给`settle`，重建相邻静态块。撤销/导入/重置及减少动态效果直接恢复；动画时序不进入作品数据。
- `VoxelSurfaceView`统一持有分块网格、动画实例、材质和纹理。重建时释放旧几何，稀疏实例替换和动画结束释放实例缓冲，卸载释放全部资源；React的`primitive dispose={null}`避免重复接管资源。几何查询仍可把面/实例映射回稳定ID；当前对话创作界面不注册方块事件。

## 逐批跟随当前物件（2026-10-11，用户决定替代整轮完成后全物件取景）

当前页面使用 `useWorkspaceWorkshop.accept` 接收后台快照；同一场景、同一 `resetKey` 且任务 `committedBatches` 增加时，比较前后快照，经 `cameraFocus.changedSceneVoxels → viewAction.frameChanges → SceneCamera.fit → CameraTween` 跟随这一批变化。打开项目、纯聊天、仅更新任务文字或未发生几何/颜色变化不触发。后台轮询可能合并两次读取之间的多个提交，此时取这次实际收到的差异，不补演未收到的中间快照。取消/失败前已经成功提交的变化仍正常显示与跟随，终态本身不额外取景。

差异以体素 ID、坐标与颜色为准：普通部件扩大到所属物件组（例如改屋顶仍看完整房子），未归组部件只看该部件；地形/水体仅包含变化的格子，避免整岛或整条河占满取景。删除先看同物件剩余成员，完全删除则看原位置。远处无关物件不参与距离计算；完整场景仍扩展远裁面。相机事件不进入保存数据，不改变后台提交、语音与撤销。旧 `workshopTurn.onSceneComplete/frameObjects` 仍是旧流测试入口，不再决定当前后台工作区的取景。

自动取景沿用当前观察方向，以镜头副本计算距离、轨道中心和投影视锥偏移；主体投影居中于整个屏幕。`cameraTween.CameraTween`同时补间中心、距离、球面方向、zoom和viewOffset，以Cubic.InOut在2200ms内结束；“回到初始视角”按钮也用同一tween，恢复全场景与默认观察方向。球面角选择较短路径，避免从目标另一侧复位时穿过中心；开始前清除OrbitControls残余惯性并保留当前显示姿态，避免与tween争抢。

## 光照与后处理

按用户最新要求使用透视观察相机、方向光投影与屏幕空间 AO，保持 Lambert 材质、原有光照强度和透明背景。当前 Three.js 为 0.186.1；复用其官方 [GTAOPass](https://threejs.org/docs/pages/GTAOPass.html)，不新增渲染依赖。N8AO 候选未采用：本项目需要明确释放 GPU 资源，核对版本的完整清理接口不足；当前方案的代价是自行管理少量后处理生命周期与透明合成。

- `SceneLighting`：主灯使用 2048×2048 的 PCFShadowMap。全局 `shadowMap.autoUpdate=false`，镜头变化复用阴影；灯光边界变化、体素同步/文档替换、动画的每一帧（包括最终落位）及减弱动态提前结束都标记 `needsUpdate=true`，在下一次beauty阶段重绘。卸载恢复原autoUpdate并释放阴影贴图。`SceneCanvas` 把当前/前一快照、0.9 格整体落位动画、尚未结束的视觉起终点和沿主光方向投射的接影地面纳入边界；阴影相机随场景更新，灯光方向不变。实例裁剪包围体同样包含动画起终点。地面仅接收半透明投影，不参与拾取。
- `ScenePostprocessing`：原始场景 → GTAO/Poisson 去噪 → 透明 sRGB 输出 → FXAA。AO 半径按世界单位计算（2.2 格），透视相机移动不会改变其世界尺度。透明接影面只从法线/深度阶段排除，避免成为错误遮挡物；beauty 阶段保留。AO 阶段复用刚生成的阴影，不再次计算阴影贴图。
- 透明输出：`RenderPass.clearAlpha = 0` 保证首次手动清屏透明；当前 `flat` 关闭色调映射，输出着色器先解除线性颜色预乘，再做 sRGB 编码并恢复预乘，避免网格和阴影边缘发白。以后改变色调映射或输出色彩空间时需同步更新该输出通道。
- 按需帧不变：动画、相机和编辑触发重绘，后处理不自行请求持续帧。容器/DPR 变化重设目标尺寸；卸载释放 composer、各 pass、阴影贴图和手工纹理（补齐 r186 GTAOPass 遗漏的两份材质）。R3F 管理声明式几何和材质，Drei 管理相机监听。

2026-10-11 验证：构建与类型检查通过；1440×1024、390×844 实际渲染、旋转、缩放、复位通过。隔离页面验证方块 ID/法线拾取及三次画布卸载重建，最终无新增控制台错误；临时页面已清理。未测真实移动设备帧率或长期 GPU 内存趋势。
